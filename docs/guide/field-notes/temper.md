# temper: hard-won lessons for redkiln (Redkiln Rust)

Mined from `/home/user/temper` at `main` 82d3176 (merge of #186, 2026-11-01), 491 commits. This complements `references/strategy/audit/temper.md` (2026-10-13, at 2b4bc04) and does not repeat its architecture. Since that audit, temper shipped 1.4.0 (2026-10-19) and 1.5.0 (2026-10-30), split its lens into its own plugin, went public, and started the 2.0 port (Phases 0a to 1c). Paths are relative to `temper/`.

## Guardrails

- **[hooks] Scan the post-edit text, and refuse only new hits.** `preEdit` rebuilds the file as it will be after the edit (`applyEdit(before, ti, tool)`), scans before and after with the same lexer, and denies only hits that `newHits` finds in the after set and not the before set. Legacy escape hatches in a touched file never block the agent, but a new `unwrap` is refused before it reaches disk, with a message that says how to request a human-approved `#[expect(lint, reason)]`. The same before/after diff counts tests and `#[ignore]`s, so removing a test or adding an ignore becomes an ask (H-12), not a deny. Evidence: `scripts/lib/hooks.mjs:251-372` (`fresh = newHits(...)` at :318, test-count ask at :327); the same diff for `cp`/`mv` onto `.rs` at :530.

- **[trust-security] The state dir is unwritable from the agent, by every route.** Verdicts and gate records live in `<git-common-dir>/temper/`. Edit and Write into `.git/` were always denied, but the 2026-10 audit found a shell redirect, `cp`, `tee` or a Python `open(..,'w')` could forge a review verdict or a green gate record, and Stop trusted it. 1.4.0 denies shell writes into the state dir, reading the command as the shell does (including `$(git rev-parse --git-common-dir)/temper/...`, `cd` into it, variables set earlier, backslash-removal tricks like `.git/tem\per`, and a bash function faking a PowerShell name). Redkiln must assume every artefact the gate trusts is forgeable unless it is protected on Edit, Write and Bash alike. Evidence: audit finding engine-1-6 (`docs/history/2026-10-audit/report.md:200`), `CHANGELOG.md:169`, c6eaac2, `scripts/lib/hooks.mjs:737` (`stateDirWrite`).

- **[trust-security] Baseline raises are a human act, enforced in three places.** `baseline --update` and `--init` refuse when `CLAUDECODE=1` unless the human sets `TEMPER_ALLOW_RAISE=1`; the Bash hook asks on the command and on restoring an older baseline with `git checkout`/`git restore`; shell writes to the file are denied; and CI flags every raise (`BASELINE RAISED`, per host) without failing. Evidence: `scripts/temper.mjs:271`, `CHANGELOG.md:297-300`, `scripts/lib/hooks.mjs:960` (`baselineRaise`), `:976` (`claudeRestore`), wi-d23383.

- **[github-ci] CI flags, never fails, on a raised baseline or a changed vendored copy.** wi-d23383 first chose "flag plus CODEOWNERS", then reversed: CODEOWNERS also gates `--tighten`, deadlocks a single-owner repository (you cannot approve your own PR) and needs a paid plan on private repos. wi-bd1cde applied the same to `.claude/temper/`: an unreleased `main` keeps the last release's `VERSION`, so "same version, different bytes" is not proof of a hand edit. The flag step runs before any vendored code, and the comment job runs no repository code. Evidence: `docs/history/decisions.md:13,90`, `CHANGELOG.md:139` (#66, #67), `CHANGELOG.md:269-273`.

- **[hooks] Config files that steer the gate are part of the tree fingerprint.** Before 1.4.0, a session that changed only `.cargo/config.toml` (`rustflags`) or the gate keys of `.claude/temper.json` stopped with no gate, and a cached green result from before the edit was reused. Now those files, and later crate charters (`AGENTS.md`), are hashed into the fingerprint; `.claude/temper.json` counts by its effective gate settings, not its bytes, so a reformat or a hook-only key does not invalidate reviews. Evidence: audit engine-1-15, `CHANGELOG.md:190`, `scripts/lib/project.mjs:751-780` (`changedGateConfig` at :777), 23f91e2.

- **[rust-craft] Fingerprint must include the resolved commits, not just the diff.** 1.2.0 fixed a bug where every clean tree hashed the same, so a gate result cached for one commit was reused for another; a `TEMPER_BASE` from another repository produced an empty diff. The fingerprint now hashes `head:` and `rev:` before the diff and untracked files. Evidence: `CHANGELOG.md:331-333` (1.2.0 Fixes), `scripts/lib/project.mjs:753-760`.

- **[llm-judgement] Verdict validation rejects degenerate evidence.** Audit engine-1-12: `files_read` matched changed files by bare suffix in both directions (`["s"]` covered everything), and every score could be `n/a`, so an approval with no rated dimension passed. Now a `files_read` entry must equal the repo-relative path or be an absolute path ending in `/` + the whole path; `correctness`, `escape_hatches` and `craft` must be rated 0-4; "approved" is invalid with a blocker/major finding, a score below 3, a red cached gate for that fingerprint, or a non-pass gate entry. Evidence: e3eb3d5, `scripts/lib/verdict.mjs:17,26-37,98-108`.

- **[testing] Every code block in the standard is compiled, linted or parsed.** `tests/doc_examples.py` compiles each ```` ```rust ```` "Do" block in a generated crate under the template's lints with `clippy -D warnings` plus the scanner; ```` ```rust,ignore,expect=clippy::unwrap_used+E0502+scan:discard-ok ```` "Don't" blocks must fire exactly the diagnostics they claim; `rust,fragment` blocks are scanned; TOML is parsed. Lint relaxations are an enumerated list (wi-39b3a1). This is how 329 examples stay true across toolchain bumps. Evidence: `tests/doc_examples.py:1-60`, `AGENTS.md` "Code in the standard is tested", audit report §1 ("0 of 329 doc examples failing").

- **[testing] Rule IDs are permanent and every citation is checked.** `tests/registry.py` checks registry rows, one section per ID, that every `[A-Z]{1,4}-NN` cited anywhere (README, skills, agents, templates, Cargo/clippy files, `scripts/**/*.mjs`) exists, and that stated rule counts ("182 rules") match. `tests/lint-claims.py` checks that every lint the standard names exists on the pinned toolchain and is enabled by the template, that scanner keys cited exist, and that `scan` rows and scanner rules agree by ID; `gen_rulemap.py --check` keeps `rulemap.json` fresh. Evidence: `tests/registry.py:1-25`, `tests/lint-claims.py:1-25`, `AGENTS.md` "Rule IDs are permanent".

- **[plugin-packaging] Vendored copies are byte-checked in CI, never hand-synced on trust.** `tests/ci.sh` diffs `scripts/` against `templates/example-workspace/.claude/temper/` and `plugins/temper-lens/scripts/`, and `rules.md` against the lens's copy; `release-check.sh` checks `VERSION`. The check caught a CodeQL autofix that edited only the lens's vendored `report.mjs` (and also broke `|` escaping in table cells): the fix was a revert and a dismissed alert, not a change to the copy. Evidence: `tests/ci.sh:40-48`, 73f2ff8.

- **[plugin-packaging] CI fails if the main plugin ships a mod.** The desktop app's Chat and Cowork turn off every part of a plugin whose `hooks.json` lists `modules`, skills included (`/temper:gate` failed with "this plugin entry is off here"). The lens moved to `plugins/temper-lens/`, and `tests/ci.sh` refuses `modules` in `hooks/hooks.json` or `types` in `plugin.json`. Evidence: `tests/ci.sh:50-54`, `CHANGELOG.md:5`, `docs/history/decisions.md:149`.

- **[process] Release notes must say how to upgrade when engine or templates change.** `tests/release-check.sh` fails a release whose CHANGELOG section does not end with an "Upgrading from X.Y" note when `scripts/` or `templates/workspace/` changed since the previous tag, and fails with `--tag` if `## Unreleased` sits above the release. Every 1.x note names exactly what drifts (for example, 1.5's per-host baseline sections are silently dropped by a 1.4 vendored `--update`, so refresh the vendored CLI in the same PR). Evidence: `tests/release-check.sh:74-110`, `CHANGELOG.md:100-101`.

- **[process] Semver is defined by impact on an adopted repository.** A new MUST rule or false-negative fix the ratchet absorbs is minor; one that fails untouched code is major; raising the minimum Claude Code or Node version is major (it can stop hooks for anyone who has not upgraded); 1.x cannot ship a major. New checks therefore fail only new or changed code (TST-09, ARC-08, mocking crates in 1.5.0). Evidence: `docs/history/decisions.md:130-133` (#36), `CHANGELOG.md:51`, wi-22c6a1, wi-c038a8.

- **[human-decisions] Freeze hook and gate behaviour while a pilot runs.** wi-b63bd6 held the behaviour-changing PRs (the `rm` ask, the `Declined:` line) unmerged until the pilot report, so pilot telemetry measured one behaviour. AGENTS.md lifts it into the unattended-session rules. wi-864860 shows the boundary: a template change pilots only get by re-running setup, and that changes no hook decision, was not held. Evidence: `docs/history/decisions.md:48,91`, `AGENTS.md` "Unattended sessions".

## Patterns

- **[hooks] Honest exits: `Status: WIP` / `Status: BLOCKED` plus a one-block loop breaker.** The Stop gate runs only if Rust changed in the turn; it parses the last `Status:` line of `last_assistant_message` (markdown decorations tolerated) and stands down on WIP or BLOCKED with a notice. Every block message ends by naming that exit. The loop breaker records, per agent context, which fingerprint was blocked for which reason; when `stop_hook_active` is set and the same tree is blocked for the same reason again, it lets the turn end with a loud notice (`stopped with a RED gate (no progress after the previous block)`). Since #135 it remembers each tree, so two red worktrees do not alternate forever. Evidence: `scripts/lib/hooks.mjs:1264-1286`, `:1623-1712`.

- **[llm-judgement] Verdicts bound to the exact tree, recorded only by the hook.** The reviewer must emit a fenced `temper_verdict` JSON carrying the 16-hex fingerprint handed to it in `SubagentStart`; the hook (not the agent) validates it against the session's changed files and cached gate, stores it under `verdicts/<fp>.json`, and marks it `stale` when the tree moved. Stop requires an approving verdict for the current fingerprint, so any edit after approval needs a fresh review. `SubagentStart` runs `cargo fmt` before a review, so formatting at Stop cannot invalidate the approval. Evidence: `scripts/lib/hooks.mjs:1193-1247`, `scripts/lib/verdict.mjs:38-46`, audit §2 (SubagentStart row).

- **[llm-judgement] Repeat reviews converge by rule, not by re-asking.** The pilot saw one unchanged tree go approved, changes-requested, changes-requested, approved, with the last verdict deciding Stop (#136). wi-39a8f0: the reviewer gets the earlier verdict as context, and a `changes-requested` with no blocker/major finding, no score below 3 and every gate entry pass cannot replace a non-stale approval; it is kept in `<fp>.history.jsonl` with `kept: "approved"`. Evidence: `scripts/lib/verdict.mjs:124-155,186-200`, `CHANGELOG.md:94-98`, wi-39a8f0.

- **[hooks] Fail open in session, fail closed in CI, and say which.** Any thrown handler becomes a `systemMessage` and exit 0; unparsable stdin likewise; `TEMPER_DISABLE=1` is the human switch. `docs/troubleshooting.md` "What fails open" lists every case (hook error, hook timeout, loop breaker, a reviewer's invalid verdict on its second try) and names CI's fail-closed gate as the layer to rely on. Evidence: `scripts/temper.mjs:76-94`, `docs/troubleshooting.md:31-40`.

- **[cli-contract] Brownfield ratchet: line-level new code plus per-crate counts.** `baseline --check` fails only on a finding in a line added, modified or moved since the base (renames recognised; moved lines count as new so a deleted `unwrap` cannot reappear elsewhere, wi-06d675), a crate's per-lint count rising (catches a new warning on an untouched line), or an `#[allow]`/`#[expect]` of a forbidden lint. Without a baseline it requires zero findings. `--tighten` only lowers, and refuses on another host (wi-cd9821). Findings are collected with `--cap-lints warn` so every crate is checked, and macro findings are attributed to the call site. Evidence: `CHANGELOG.md:283-305`, `scripts/lib/baseline.mjs`, `docs/history/decisions.md:82-83`.

- **[cross-platform] Baseline counts per host triple.** A Linux-recorded baseline was always red on Windows because `cfg(windows)` code adds clippy counts (redkiln-rs: 7 counts over in two crates, #141). The baseline now keeps the recording host's counts in `totals` and others under `targets.<triple>`; `--init` on a new host adds a section; checks compare with the running host's section; a host with no section stays red with a message naming the fix (wi-2771a4: trusting another platform's counts silently is an H-12 call). Evidence: `CHANGELOG.md:43-49`, `scripts/temper.mjs:257-273`.

- **[observability] Lost-gate detection by heartbeat.** A `gate-start` row with no outcome meant the Stop hook was killed, but not whether by its 1200 s timeout or by an interruption (7 of 16 Stop gates in one redkiln-rs session, #137). `gate-start` now records pid and the hook's timeout, a worker-thread heartbeat writes every 10 s (cargo blocks the main thread), and the next hook logs `gate-lost` with `reason` timeout (alive within 30 s of the deadline), interrupted, or unknown. Evidence: `scripts/lib/hooks.mjs:1305-1400` (`BEAT_MS` at :1318, `lostGateRow` at :1359), `CHANGELOG.md:92`.

- **[hooks] Budget the Stop hook against its own timeout across trees.** With several changed worktrees, Stop gates each in turn and, after 540 s, blocks before starting another uncached gate ("End the turn again to run it"), so a gate is never cut off mid-run by the 1200 s hook timeout (wi-4521a7). Separately, a step's own timeout (900 s) is below the hook timeout, and a red timeout result is cached (needs `--no-cache`). Evidence: `scripts/lib/hooks.mjs:1621-1648`, `docs/troubleshooting.md:159-173`.

- **[observability] Telemetry from disposable containers through a dedicated branch.** Cloud containers lose `.git/temper/`; the cloud git proxy refuses hidden refs. wi-641f99: opt-in `telemetry.branch`; each Stop spawns a detached, unref'd `temper telemetry push` that commits `sessions/<date>-<session>.jsonl` with a private index and `[skip ci]`, touching no working tree, index, HEAD or branch; a failed push is retried at the next Stop. Evidence: `scripts/lib/hooks.mjs:1720-1733` (`shipTelemetry`), `CHANGELOG.md:143`, wi-641f99.

- **[trust-security] Redact command text by dropping every quoted string.** Telemetry needed denied command text (#138), and three reviews in a row found secret literals the regex patterns missed. wi-f4e663 chose to drop the contents of every quoted string, then apply secret patterns to the rest, redacting before clipping. Evidence: `scripts/lib/project.mjs:491-545` (`dropQuoted`), 890fffd, 15074b0, wi-f4e663.

- **[hooks] Deny messages that stop retries by naming the sanctioned route.** Workflow subagents kept retrying denied `git apply` patches (28 of 42 interim denials were Workflow subagents, 19 `via: patch`), and the read-only reviewer tried to apply patches 13 times (#140). The deny now names the routes that keep the checks (Edit/Write, or commit in the worktree and `git cherry-pick`/`git merge`) and says a retry is denied again; the reviewer may not run `git apply`/`git am`/`patch` at all. Evidence: `CHANGELOG.md:39`, e33efa4, issue #140.

- **[headless-agents] Hook context for preloaded subagents.** Temper's three agents start with the standard preloaded and are exempt from the skill gate (`PRELOADED`); `SubagentStart` injects root, base, fingerprint, changed files, cached gate and plans, and for the reviewer the fingerprint the verdict must carry and any earlier verdict. Everyone else is denied Rust edits until the Skill tool or a Read of `SKILL.md` writes a per-agent marker. Evidence: `scripts/lib/hooks.mjs:31-33,279-286,1249-1262,1773`.

- **[testing] Rubric-graded evals with two groups and paired arms.** Cases are tagged by what they were built to show: `discriminating` (mean Δ >= +0.4 with vs without plugin) and `regression` (Δ >= 0 per case, the plugin never makes things worse); new cases are `candidate` until an owner-approved run places them. A case that stops separating the arms (the plain model learned to ask before adding a crate) moves to `regression` rather than being tuned. Results: +0.42 (2026-10-05) to +0.61/+0.53 (1.4.0 RC, $10.53) to +0.57 (1.5.0 RC, 22 cases, $17.74). Evidence: `docs/history/evals.md:5-27,29-60`, `docs/history/decisions.md:134-138`.

- **[process] Two-way calls are taken and logged, one-way calls wait.** Every agent assumption or default goes through Weigh-In and lands in `docs/history/decisions.md` with why and an anchor to reopen it (dozens of rows, including port defaults wi-a5a813..wi-5f034a). Agents may merge under a fixed bar (all checks green, no conflict or open thread, cited fresh-context approval, wi-880b66), and an approval survives a merge of `main` whose only conflict was CHANGELOG or the decision log (wi-7f5046, wi-7e8bf0). Evidence: `docs/history/decisions.md:64-110`, `AGENTS.md` "Unattended sessions".

## Gotchas

- **[hooks] A timed-out PreToolUse hook lets the command run.** So a slow regex is a bypass, not a delay. #155 found `python3 -c "'busybox` + 64K spaces took about 27 s in `codeWriteTargets` (15 s timeout); `'('` x100,000 took 12.8 s in the grep-pattern blanker; 1.5's follow-up found 16K `write_text` took 16 s and 32K `sed ` over 20 s, because each pattern rescanned the segment from every keyword. Fix: `fromFirst` tries a sticky regex once per segment from the first keyword, plus 1 MB timing tests (3 s limit on Windows, which runs about 2x slower). Redkiln's guard must be linear-time by construction (the port chose `regex` for exactly this, wi-e9386f). Evidence: issue #155, `CHANGELOG.md:27-29`, `scripts/lib/hooks.mjs:339-358`, 84d2a0f, wi-779016.

- **[hooks] A hook that "never fires" in local tests may be the only path in cloud sessions.** Smoke runs on Claude Code 2.1.286-2.1.302 never called `PreToolUse SubagentHandback`, so wi-103aa0 removed it. In cloud sessions a subagent's report goes only through `SubagentHandback` and `SubagentStop` gets no `last_assistant_message`, so every cloud session that changed Rust ended `BLOCKED` on PROC-08 until #97 restored it. Both paths now record, deduplicated by a one-shot verdict hash. Test hooks on every surface (CLI, cloud, Cowork) before removing one. Evidence: `docs/history/decisions.md:37`, `CHANGELOG.md:147,135`, `scripts/lib/hooks.mjs:1213-1229,1242`.

- **[plugin-packaging] Plugins do not reach cloud sessions via `.claude/settings.json`, and a SessionStart install is too late.** A cloud session clones fresh; `extraKnownMarketplaces` registers only in a trusted workspace and `enabledPlugins` never installs (`plugin-cache-miss`); account plugins sync to `~/.claude/plugins/synced/` only for the right organization; an uploaded zip never updates; installing from SessionStart succeeds but loads next start. Only the environment setup script works. Chat loads skills and ignores hooks and agents. Evidence: `docs/troubleshooting.md:42-58`.

- **[distribution] npm optionalDependencies do not reach claude.ai-synced or Cowork installs.** temper's own probe plugin (`binprobe`, 2026-10-01): Claude Code's npm auto-install did not run for a synced plugin in Cowork (no `node_modules`); the docs say dependency install runs only when Claude Code copies a plugin into its cache, which synced plugins skip. Executable bits did survive upload and sync, exec-form `node` hooks ran, and cargo is in neither Cowork image. This is why redkiln reopened D1/D6/D13 for `libexec/<target>/` bundling. Evidence: `docs/research/shipping-native-binaries/report.md:126-160`, `references/docs/blueprint.md:51,361`.

- **[distribution] Marketplace installs only move when `plugin.json`'s version changes.** A fix merged to `main` does not reach existing marketplace installs until a version bump; new installs and org sync read `main` directly, so `main` must always be releasable. Evidence: `AGENTS.md` "`main` is what users get", f7755ab, `CHANGELOG.md:133`.

- **[cross-platform] Windows paths and processes.** Cargo reports verbatim paths (`//?/C:/...`); TEMP is often an 8.3 short name (`RUNNER~1`) while git gives the long one; macOS TMPDIR is under the `/var` -> `/private/var` symlink; all were fixed by comparing real paths whenever the lexical path leaves the root. Append-mode handles cannot truncate on Windows (`PermissionDenied`), so the example store writes at explicit offsets. Hooks start `node` with no shell, so `.cmd` shims from version managers fail and PATH must be set in the user environment, not `$PROFILE`. Windows reuses pids fast (a "dead pid" test flaked) and a detached child holds directories open (EBUSY in cleanup, needed 30 s retries). Evidence: a485408, 2d8e9a4, 8be0683, f878324, a9a1304, 2987a4a, 797dc55, `docs/troubleshooting.md:185-193`.

- **[plugin-packaging] Plugin mods are behind a per-account rollout switch.** The lens did not load on the owner's Windows machine on Claude Code 2.1.289 and 2.1.303 (only built-in hooks modules loaded); it loaded on Linux 2.1.303. A mod that throws at load leaves every settings hook running. Plugin API types are written only when an interactive session loads a mod, so CI vendors them (`tests/lens-types/`) to type-check. Evidence: `docs/history/evals.md:76,117-122`, `CHANGELOG.md:105`.

- **[git] Root `CLAUDE.md` is rejected when the repo root is the plugin root.** `claude plugin validate --strict` refuses it because a plugin never loads it; project memory lives in `.claude/CLAUDE.md`. In a monorepo the rule moves to each plugin directory. Evidence: `AGENTS.md` "No `CLAUDE.md` at the repository root", `docs/plans/v1-readiness.md:88`.

- **[github-ci] `npm publish tarballs/x.tgz` is read as a GitHub `user/repo` shorthand.** The first 2.0.0-alpha.1 run failed before publishing; it needs `./tarballs/<file>.tgz`. Evidence: `CHANGELOG.md:7`.

- **[github-ci] Required checks are matched by job name, and claims about rulesets drift.** The 2026-10 audit found temper's `main` ruleset required no status checks at all, and the pilots' rulesets did not require the temper gate, though AGENTS.md, CONTRIBUTING.md, the plan and a closing comment all said they did. Fixed by owner edits (wi-2d6d35, wi-1f933a). Reverting CI from self-hosted to GitHub-hosted runners kept job names so required checks still matched. Evidence: `docs/history/2026-10-audit/report.md:16,483-486`, febcd6a.

- **[llm-judgement] Eval judges see only the final message.** Correct plugin runs lost grades because the last message was only a status block ("Status: DONE ... Review: approved") and did not repeat that the failing test was kept, not ignored. This produced the `Declined:` line in the Status block (#48). A `haiku` judge also failed a correct reply (−0.17). Evidence: `docs/history/evals.md:20,279`, the 2026-10-06 `reviewer-rejects-clone-to-compile` note (#48), `CHANGELOG.md:141`.

- **[headless-agents] Headless eval runs cannot answer asks or run slash commands fairly.** `new-crate-gets-charter` scored the plugin arm lower (0.11 vs 0.33): the hook asks before a new crate and a headless run cannot answer, so two plugin runs wrote no code. A prompt that starts `/temper:implement` reaches only the plugin arm (plain arm gets "unknown command"), so cases use plain English; `/temper:setup` (AskUserQuestion) and the 3-round review cap are untestable in evals. Evals run without `Bash` (no sandbox in the container), so no arm can run the gate. Evidence: `docs/history/evals.md:64-67,150-151`, wi-852ab8.

- **[llm-judgement] The baseline model drifts under your evals.** `asks-before-new-dependency` stopped separating the arms as the plain model began asking on its own; its replacement asked in 8 of 8 paired runs on 2026-10-06, then added a crate unasked in 3 of 3 on 2026-10-18. Unpaired probes differed from paired runs. Re-run and re-group rather than trust one run. Evidence: `docs/history/evals.md:109` and the 2026-10-06 #47 sections.

- **[cli-contract] Porting a regex scanner means porting the regex dialect.** The Rust port keeps 1.x's JS patterns verbatim and translates them at `Scanner::new`; it had to reproduce JS `m` (`^` after lone `\r`, U+2028/2029), ASCII-only `i` folding, look-around via hand predicates that mimic JS backtracking, and back-windows counted in UTF-16 units, and rejects constructs `regex` reads differently. Byte-identical parity was the only way to ship without re-litigating 56+ rules. Evidence: `docs/history/decisions.md:154,159-164` (wi-962170, wi-31f653, wi-afd1cd, wi-1636ef, wi-d31f39, wi-7256fa).

## Lessons from history

- **[trust-security] Shell guards are an arms race; scope fail-closed to where it is cheap.** #151 went through nine review rounds, each finding another way a patch reached `.rs` files unseen (`gpatch`, `git-apply` at any path, `busybox`, `$'...'`, `env -S`, git aliases, `trap`, awk `system()`, `bash -c --`). wi-9792d6 shipped a smaller safe core: for the read-only reviewer alone, anything temper cannot read exactly (non-literal command names, unresolvable git subcommands, shells fed from expansions) is denied; other agents keep best-effort reading, backstopped by the Stop gate and CI. wi-0e226b rejected emulating `echo`/`printf` as unsound and quadratic. Evidence: `docs/history/decisions.md:107-110`, `CHANGELOG.md:61-83`, `scripts/lib/shell.mjs:1511-1603` (`opaquePatch`, `unreadScript`), 14c644b.

- **[hooks] Literal pattern matching on whole commands gave false positives in prose.** The Bash hook denied `git commit -m "docs: mention --no-verify flag"` and `cargo clippy --fix --allow-dirty`, and `RUSTFLAGS=-L/opt/My-App/lib` read as `-A`. The fix blanks message-like option values, here-document bodies and grep patterns first, but not here-docs a shell or interpreter reads, nor values containing `$(...)`. Its first version opened regressions (backslash continuations, `cargo clippy -p grep`, `git -C commit-tools`, cubic backtracking) that review caught. Patch-level, released with "deny -> allow" and "allow -> deny" lists. Evidence: audit engine-1-17, `CHANGELOG.md:171-175`, d001fde, `scripts/lib/hooks.mjs:1018,1146`.

- **[hooks] Subagent worktrees bypassed the Stop gate.** Workflow subagents edit in `.claude/worktrees/agent-*`; Stop looked only at the main checkout, so their Rust was never gated or review-bound (redkiln-rs: 9 reviews on one fingerprint, no Stop row). It went live as a written P1 exception because CI's required check still gated every PR, then was fixed in 1.5 by recording every checkout an agent touches, with its starting tree, and gating each still-changed worktree (#135); #157 closed two more scope gaps. Any redkiln gate keyed on cwd must handle worktrees. Evidence: issue #135, `CHANGELOG.md:25,85`, `docs/history/decisions.md:136`, `scripts/lib/hooks.mjs:1432-1620`.

- **[testing] The headline paths had no deterministic tests.** The 2026-10 audit found Stop, SubagentStop, verdict validation, SessionStart and the skill-gate deny were covered only by paid smoke runs and evals, and `evals.md` claimed unit coverage that did not exist. Since then `tests/handlers.test.mjs` and friends cover them. Evidence: audit engine-1-9 (`docs/history/2026-10-audit/report.md:28,203`), `docs/history/evals.md:361`.

- **[cost-capacity] Gate latency on a big brownfield repo nearly exhausts the Stop budget.** redkiln-rs uncached gates took 60-526 s (p50 274 s) against weigh-in's p50 26 s; 7 of 16 Stop gates in one session ended with no outcome. The 1.2 setup also showed that missing `allow-*-in-tests` keys in `clippy.toml` made the baseline record 5,541 test-code findings as debt. Evidence: issue #137, `CHANGELOG.md:221-224` (1.3.0 setup `manual` lines).

- **[process] Pilots expose misfits the plan never imagined.** The six pilot findings (#135-#141) were all about how agents actually work: worktrees, Workflow patching, non-converging reviewers, missing telemetry fields, and the per-platform baseline. None was a scanner false positive. The pilot needed a recovery decision when redkiln-rs pushed no telemetry (wi-2c680d). Evidence: issues #135-#141, `docs/history/decisions.md:54,136`.

- **[human-decisions] H-16 is not applied to implied API breaks.** In the 1.4.0 RC every run, with and without the plugin, changed `parse_port`'s public signature before asking; the plugin runs listed it under "Decisions needed" after making it, and the reviewer treated "your request is the approval". OUT-03 (versioned JSON) was also not applied unprompted in either arm. Evidence: `docs/history/evals.md:110-111`.

- **[process] 1.3.0's MSRV job was hard-coded.** The template's `msrv` job used 1.96, so it failed in every adopter whose `rust-version` was newer; it now reads `rust-version`. Pilots also found adopters' `-D warnings` steps would fail every legacy finding once lint tables merged, which became `setup`'s `manual` lines. Evidence: `CHANGELOG.md:218-226` (#32), 1398194.

## Open problems

- **[trust-security] The independent review is only re-checked in session.** CI gates fmt/clippy/tests/scanner but nothing outside the session verifies that an approving verdict existed for the merged tree (assay deliberately does not consume the verdict, ADR-06). A session ending with `TEMPER_DISABLE=1`, the loop breaker or a `WIP` exit ships unreviewed code that CI accepts. Evidence: audit report §1 ("nothing outside the session re-checks the independent review"), `docs/troubleshooting.md:37-40`.

- **[trust-security] Shell-guard coverage is still heuristic for non-reviewer agents.** #155 left `toybox patch`, `script -qc`, `flock`, `parallel`, `git submodule foreach`, `git rebase --exec`, deno eval and pwsh `-EncodedCommand` accepted for most agents, backstopped by Stop and CI (wi-779016). `cp x.rs "$DEST"` to an unknown destination is accepted by decision (wi-8b8a16). Evidence: issue #155, `CHANGELOG.md:35`, `docs/history/decisions.md:44,59`.

- **[llm-judgement] Reviewer determinism is managed, not solved.** The #136 rule stops minor-only reversals of an approval, but verdict quality still varies run to run, and a reviewer can loop (8 changes-requested reviews on one tree in the interim report). The 3-round cap lives only in `/temper:implement` text and cannot be evaluated. Evidence: issue #136, #135 body, `docs/history/evals.md:150`.

- **[rust-craft] 17 MUST rules are review-only by design, 11 more advisory-only.** Each new check could fail code adopted repositories never touched, and cargo-deny cannot express per-member layer bans (wi-a8e89f). These depend wholly on the LLM reviewer. Evidence: wi-3fa7cf, wi-b7db11, wi-74c9a0, `CHANGELOG.md:51-59`.

- **[testing] Several eval candidates fail in both arms or have broken graders.** `new-crate-gets-charter` (grader throws on a missing file; headless ask), `bugfix-adds-regression-test` and `injects-clock-for-tests` (no `Bash`), `plans-before-new-module`; evals never run the gate because the container has no sandbox for `Bash`. Evidence: `docs/history/evals.md:64-72`.

- **[cost-capacity] Gate time on large workspaces vs the 1200 s hook budget.** Guidance is warming the cache from a terminal, nextest, sccache and trimming steps; the hook cannot run longer, and progress only starts after `cargo fmt` because the progress file is keyed by the post-format fingerprint. Evidence: `docs/troubleshooting.md:159-173`, `docs/history/evals.md:81`.

- **[distribution] The port still ships through npm.** `release-2.yml` publishes `@wet-ink/temper-*` and `scripts/fallback.mjs` builds with the user's cargo, while the blueprint decided libexec bundling; both the D1/D6/D13 reversal and the state-compatibility invariant against Core's happenstance store are open in temper itself. Evidence: `CHANGELOG.md:9-15`, `references/docs/blueprint.md:51,361`, audit §8.1, §8.3.

- **[cli-contract] Nested workspaces are unsupported.** Discovery takes one `Cargo.toml` root; only the port plan says so. Evidence: audit engine-1-18 (`docs/history/2026-10-audit/report.md:211`).
