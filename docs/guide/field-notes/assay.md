# assay (to become Redkiln Review): hard-won lessons

Mined 2026-11-01 from `/home/user/assay` at `34cce61` (398 commits; the audit read `3c7e9da`, 46 commits, on 2026-10-13), plus GitHub issues and PRs #1 to #361, `docs/review/` (three adversarial rounds), both handoffs, `docs/decisions/0004-0007`, the crate charters and the root `AGENTS.md` decisions log. `/home/user/assay-ledger` holds only its initial commit (`3ae05eb`); the ledger's shape lives in assay's code. This file skips what the audit already covers (crates, zones, data stores, Core candidates) and keeps to lessons.

## Guardrails

- **[trust-security] Fail closed is written down as a named policy and given to every security story up front.** wi-b5affa ("refuse rather than model") is cited in nearly every decisions-log row from #88 onward. Each two-way call in a gap the spec left open is settled toward less eligibility: absent lists are empty, web-flow as author taints, no push clock means no approval (wi-3981eb). An unreadable lease fails acquisition and is never reaped (wi-850eb7). A 404 counts as an absent ledger file only once the token can see the repo (wi-67ab73). The handoff makes this a briefing rule: "Brief every security-control story with it up front." Evidence: `docs/handoff-2026-10-12.md` ("How the run worked"), `docs/handoff-2026-10-19.md` calls table, `AGENTS.md:82-110`.

- **[testing] Reviewers kept blocking on the same three gaps, so implementer briefs now require them.** These are a worst-case complexity table for every loop over PR-controlled input, one test per refusal branch, and boundary tests at the cap and at cap+1. Reviewers blocked on exactly these gaps on #64, #56 and #76. The pattern did not stop there: #184 records quadratic path handling on main (`git/copy/link.rs:564`, `temper/layout.rs`, `temper/head.rs` `line_text`), found in round 4 of #64. Later round-1 findings kept being "the new refusals need tests" (#281, #286, #289). Evidence: `docs/handoff-2026-10-12.md` "Brief implementers"; #184; `docs/handoff-2026-10-19.md` log 06:30, 09:20, 11:45.

- **[github-ci] Repository tests parse the workflow YAML and enforce two allowlists, and they caught an owner-made infra change.** `workflow_cache.rs` says a job is decision-bearing unless exempted by name, and such a job may use only actions known to be cache-free (ADR-21: a run's runtime token can pre-seed the Actions cache under the base scope, and a poisoned entry outlives the merge). `release_workflow.rs:145` requires `owner/repo@<40 hex> # <tag>`. When Actions billing ran out, the owner moved CI to Blacksmith through a vendor wizard PR (#302). Its `useblacksmith/checkout@v1` was unpinned and caches, and two of these tests failed at once. #304 restored the pinned `actions/checkout` (wi-8a054a), and `f414239` later reverted the whole migration. Evidence: `crates/assay-cli/tests/it/workflow_cache.rs:1-30`, `release_workflow.rs:126-145`, #302, #304, `f414239`, `docs/handoff-2026-10-19.md` "Read this first".

- **[trust-security] Re-runs are forbidden twice over: in the template and in the binary.** Round 3 found that a re-run of only the `review` job reuses `admit`'s outputs and so spends with no admission. Re-running `gates-test` launders flakes. Re-running a 29-day-old run brings back that run's workflow and binary with today's secrets (R3-05). The rule: every secret-bearing job carries `if: github.run_attempt == 1`, it ships in the first template so no unguarded version ever exists, and the binary refuses `GITHUB_RUN_ATTEMPT != 1` before reading any token. Evidence: `docs/review/03-adversarial-review-round-3.md` R3-05; `crates/assay-cli/src/main.rs:168,214`; `AGENTS.md` rows ST-10, ST-11, ST-14 ("refuse attempt != 1 before any token").

- **[trust-security] Fork PRs became untrusted the day the repo went public, and a pinned test is required.** Making the repo public (free Actions minutes) turned "fork PRs out of scope" into a live threat. Decision 0006 requires every `pull_request_target` workflow to refuse a PR whose head repo is not this repo before any secret-bearing job. The refusal is a completed `failure` with a reason, never a skipped check, and a test pins the guard. The owner also turned on approval for all external contributors' workflow runs. Evidence: `docs/decisions/0006-public-repository.md`; `AGENTS.md` row #60 ST-2 (exit 2 for another repository's payload).

- **[trust-security] The ledger accepts only records byte-identical to what assay writes.** A hand edit, or serde's array-form leniency, could smuggle in a record that parses but was never written by assay. Reads refuse anything that does not round-trip byte for byte through `to_line`. Contract reads also refuse duplicate keys and documents over 8 MiB, through a serde visitor. Evidence: wi-0351d8; `crates/assay-app/src/ledger/lines.rs:63`, `ledger/error.rs:89`; `AGENTS.md:79` (#145).

- **[trust-security] Every cap on a write is sized so the file can always be read back.** Ledger files are capped at 4 MiB so that the largest file's blob response fits the forge's 8 MiB response cap: "a file the app writes must read back" (wi-c8f4d6). Caps are paired everywhere: lease messages (`MAX_LEASE_MESSAGE_BYTES`), `--events` lines (64 KiB) and streams (16 MiB), and a 32 MiB transcript cap that charges the full budget when hit. Evidence: `docs/handoff-2026-10-19.md` calls; `crates/assay-forge/src/github/ledger_refs.rs`; `crates/assay-runner/src/headless.rs:28`; `AGENTS.md` #130 row.

- **[headless-agents] The `claude -p` environment is built from nothing, with names reserved by construction.** `HeadlessEnv` inherits nothing. It sets the OAuth token and `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, and cannot pass `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_PLUGIN_DIRS` (which loads mods from folders), provider variables, or the `LD_`, `DYLD_` and `NODE_` prefixes. `NODE_OPTIONS` loads code, and `NODE_EXTRA_CA_CERTS` behind a proxy can intercept the token: a review finding, #149. `Debug` prints variable names only. Preflight fails if any `ANTHROPIC_*`, `CLAUDE_CODE_USE_*` or cloud variable is set, even to an empty value. Evidence: `crates/assay-runner/src/headless/env.rs:1-60`; corpus case `rd-runner-classify-env` (#148 round 1); `docs/architecture/03-contracts.md:293`.

- **[cost-capacity] No API key may sit beside the subscription token, and `--bare` is banned.** In `-p` mode `ANTHROPIC_API_KEY` takes precedence over `CLAUDE_CODE_OAUTH_TOKEN`, so runs would be billed at API rates without anyone noticing. `--bare` ignores the OAuth token. Decision 0007 makes the subscription token conditional: it lives in the `assay-review` environment only (never as an org secret), it reviews no fork PR, and the terms are re-checked quarterly. Evidence: `docs/decisions/0007-subscription-token-in-ci.md`; `03-contracts.md` §8 rules.

- **[process] Merge bar for unattended runs, and how scope creep is cut off.** The bar: CI gate and msrv green, `temper:rust-reviewer` approves the PR head, merge pinned to the head SHA. Minors and nits go to a follow-up issue rather than another review round. wi-73d2d6: a review whose only objection is code already on main counts as approval, because a stale temper session base (`d2e7ac0`) made reviewers re-scope merged code. Reviewers must `cd` into the PR worktree, since they bind to the cwd tree. Evidence: `docs/handoff-2026-10-12.md` "Merge bar", "Reviewers".

## Patterns

- **[trust-security] The publication sanitiser makes model prose inert by construction instead of parsing Markdown.** Every ASCII punctuation character is backslash-escaped, so no Markdown construct can start. `@` and `#` become their fullwidth forms. `://` becomes `[:]//`, `www.` becomes `www[.]` and `gh-<digit>` becomes `gh[-]`. Leading whitespace is dropped (no indented code), and control and format characters become U+FFFD. The only live links are permalinks the publisher builds, and the only fences use a closed info-string list that has no `suggestion`, so no one-click change can be offered. The accepted residuals are written down: bare commit SHAs, and a repository's own autolinks. Evidence: `crates/assay-app/src/publish/sanitise.rs:1-120`; `AGENTS.md:82` (#88); #175.

- **[events-store] Compare-and-set is used only where the platform really provides it, and a lock is built where it does not.** The Contents API PUT carries the blob sha, a genuine CAS. `POST git/refs` fails on an existing ref, so creating a lease is atomic. But `DELETE /git/refs` takes no precondition, and updating a check run takes no expected value (R3-06(d), R3-09). So refs are deleted only by `git push --force-with-lease=<ref>:<commit> <ledger> :<ref>`. Check writes happen under a per-head publish lock: a ref `lock-<repo_id>-<head_sha>` with a 2-minute TTL. Lease commits are parentless empty-tree commits whose message is the lease. Evidence: `crates/assay-forge/src/github/ledger_refs.rs:1-35`; `crates/assay-forge/src/git/push.rs:187-218`; `docs/review/03-adversarial-review-round-3.md` §5 ("attacks tried that failed").

- **[events-store] One bounded CAS loop with no sleeps.** `compare_and_set` runs read, change and conditional write. On a conflict it re-reads and re-runs the change closure, which must derive everything from the contents it is shown. After `MAX_CAS_ATTEMPTS` (5) it ends in `Contended`. The port has no clock or sleep, so tests need no time control. Evidence: `crates/assay-app/src/ledger/cas.rs:1-80`; wi-d261b1.

- **[cost-capacity] Deadlines under locks are a type, checked before every send and every retry wait.** The adapter honoured `Retry-After` for up to 60 s, so a write that started inside the 2-minute lock TTL could land after another holder took the lock. A safety margin sized to the retries would not fit in the TTL (#290). `Deadline::admits(now, span)` accepts only work that ends strictly before the lease's `expires_at`, and refuses a sum the clock cannot hold. `LockedWrite { update, deadline }` makes it impossible to call a check write without one, and the adapter returns `ForgeError::PastDeadline`. #332 extended this to decide's publication. Evidence: `crates/assay-app/src/forge/deadline.rs`; `crates/assay-app/src/forge.rs:112-115`; `crates/assay-forge/src/github/api.rs:105-145`; #290, #332, `AGENTS.md:88,100`.

- **[cost-capacity] The slot is released after review rather than after decide, and an unknown cost is charged at the cap.** A separate `release` job (`needs: [admit, review]`, `always()`, attempt 1) frees the slot by CAS on admit's `lease_commit` and writes the `final` cost record. The amount is the real `cost_aeu` for a successful review, otherwise the reservation. `admit` writes a `reserved` record when it takes the slot, so cooldowns count admissions rather than completions. A killed review can therefore never spend unmetered. Evidence: R3-06 patch; `AGENTS.md:99` (#60 ST-10); `crates/assay-app/src/release.rs`.

- **[headless-agents] The stream-json result decides, and stray lines cannot launder an ending.** Only `rate_limit_event` (kept when `rejected` or `allowed_warning`), `assistant` (`error: "rate_limit"`) and the last `result` matter. Other kinds are skipped, so new message types do not break calls. A budget, turn or quota ending is final whatever else the transcript holds. An unreadable line only stops a success from counting. The exit status is ignored, and cost falls back to the budget when it is missing, on timeout, or when the output is capped. Each outcome has a fixture per CLI version. Evidence: `crates/assay-runner/src/stream.rs:1-120` and its tests; `crates/assay-runner/tests/fixtures/stream/README.md`.

- **[headless-agents] Every flag is proved by a canary rather than trusted.** The init must be clean: `tools` exactly Glob, Grep and Read, no MCP servers, and every plugin, skill and agent a built-in on a pinned allowlist. A hook canary plants hooks at user, project and in-tree scope and passes `--include-hook-events`. A fence canary asks for `Read //proc/self/environ`. A mod canary and an AGENTS.md canary write their canary word in two parts. "A flag that is accepted but ineffective is therefore caught by observation." Evidence: `docs/architecture/03-contracts.md` §8; `crates/assay-runner/src/headless/canary.rs`; `crates/assay-runner/tests/fixtures/plugins-2.1.296.toml`.

- **[llm-judgement] The eval corpus is mined from the repo's own review rounds.** Each `corpus/dev` and `corpus/test` case is a PR head where a reviewer later found a real defect. The case id gives the PR and round, plus the reviewed head and the fixing commit (for example `rd-runner-classify-env`: #148 round 1, `fa5781e`, fixed in `4a32491`). True-negative cases are review-round changes that drew no later finding. Labels stay outside `tree/`, which is all the reviewer may read. Acceptance runs each case k = 3 times; it fails if any case flips from at least 2/3 detected to at most 1/3, or if noise rises above the baseline's 95% Wilson upper bound. Evidence: `corpus/dev/README.md`; `crates/assay-app/src/eval/corpus.rs`; `AGENTS.md` "Prompt and rubric changes".

- **[trust-security] Commands are events, not state, so an edit can only revoke one.** Round 3 found that any writer can edit an owner's comment into `/assay override` (R3-02). decide-only now parses a command only from the payload of the `issue_comment.created` event that triggered it. It appends an App-authored command record (`commands/<repo_id>/<pr>.jsonl` with `head_sha` and `body_sha256`) and re-fetches the comment on read. A deleted comment, `updated_at != created_at` or a different hash voids the record. Evidence: R3-02; `AGENTS.md:106` (DO-1); `crates/assay-forge/src/github/event/` (DO-3: a created comment whose sender is not its author is refused).

- **[llm-judgement] A fingerprint is computed in one place, from defined fields, with length prefixes, and fails closed.** SHA-256 runs over the class, the file, the enclosing symbol, the first line of evidence that has content (normalised) and, for an omission only, `expected_behavior`. Each field carries a big-endian length prefix so no boundary can move, followed by the occurrence index. Title, body and severity are excluded, so different wordings of the same defect match. Evidence with no line of content gets no fingerprint and is disposed of as `evidence-missing`, so nothing can be waived against it. One round-1 finding: an elided first evidence line merged different defects (corpus `rd-fingerprint-elided-line`). Evidence: `crates/assay-domain/src/fingerprint.rs:1-60`.

- **[trust-security] Waiver bindings strip per-run fields.** Every gate document embeds the per-head `run_key`, so binding a waiver to whole-document digests meant no waiver ever carried to a new head (#291 round 1). The binding is now the sha256 of the canonical JSON without `source.run_key` (wi-bc5341). It is still very coarse: see Open problems. Evidence: `docs/handoff-2026-10-19.md` log 14:00; `crates/assay-app/AGENTS.md:59`; #292.

- **[git] Hardened git for PR objects treated as data.** `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL=/dev/null` and `core.hooksPath=/dev/null` are set. Only the `https` protocol is allowed. Fsck runs on fetch. `attr.tree` is set to the empty tree, because a bare repo otherwise reads HEAD's `.gitattributes`, and `-diff` turns numstat counts into `-` even with `--text`. Diffs run with `--no-ext-diff --no-textconv`. Every git process leads its own process group. The gates-lint checkout is checked against the fetched head tree: kinds, execute bit, bytes and symlink targets. Evidence: `docs/architecture/03-contracts.md` §9; `AGENTS.md:104` (ST-8).

- **[headless-agents] The prompt goes on stdin from an anonymous file.** Linux caps one argv string at 128 KiB (`MAX_ARG_STRLEN`), which a context pack can exceed, and stdin cannot be mistaken for an option. Using a file rather than a pipe means no writer can block. The CLI leads its own process group and the whole group is killed on every path. A call returns only once the group is shown gone. `may_have_run()` tells the caller whether to charge the budget. Evidence: wi-9fe37e; `crates/assay-runner/src/headless.rs:40-115,197-223`.

## Gotchas

- **[headless-agents] Tool allowlists do not remove Bash.** The built-in read-only Bash set (`cat`, `ls`, `grep`) bypasses `--allowedTools`. `Bash(rg:*)` allows `rg --pre <cmd>`, which is arbitrary execution, and `git show --output=<path>` writes files. Reviewers reproduced both. Only `--tools Read,Grep,Glob` (plus `--restricted`) removes the tool. Evidence: `docs/architecture/05-security.md` T2; `03-contracts.md` §8 "No Bash".

- **[headless-agents] Settings keys at the wrong level are silently ignored.** `blockReadsOutsideWorkingDirectories` must be nested under `permissions` and needs CLI 2.1.257 or later. Spec v1 put it at the top level, where it did nothing. `--verbose` is required with stream-json under `-p`. `--safe-mode` also disables `--plugin-dir`. Evidence: `03-contracts.md` §8; `crates/assay-runner/src/headless.rs:33-35`.

- **[headless-agents] `--safe-mode` still loads built-in mods, skills and agents.** CLI 2.1.296 under the hardened profile lists `cc-plugin-agents-md`, `cc-plugin-telemetry` and `cc-plugin-plugin-authoring`, plus about 19 skills and 4 agents, in `system/init`. So "clean" has to be an allowlist pinned per CLI version, not "empty". The owner accepted Anthropic-bound telemetry from Z3 (wi-8c8bdd). Evidence: `crates/assay-runner/tests/fixtures/plugins-2.1.296.toml`; `docs/design/assay-mod.md:56-57` (wi-1fc020).

- **[cost-capacity] Cost exists only in the final `result`, and SIGTERM loses it.** `total_cost_usd` is a client-side list-price estimate. `--max-budget-usd` can overshoot by one response (fixture `budget_exhausted.jsonl`: 0.7512 against a 0.74 cap). SIGTERM gives exit 143 with no result. So assay never kills on its own accounting: the hard stops are the CLI's caps and a wall clock, and the cap is charged on timeout. `rate_limit_event` fires with `allowed` routinely. A `setup-token` token has only `user:inference` scope and cannot read plan utilisation, so the v1 "pause at 70%" rule was removed (A-13). Evidence: `docs/architecture/06-operations.md:8-16`; `03-contracts.md` §8.

- **[cost-capacity] Review and authoring share one subscription window.** The first AFK run was paused at 90% weekly usage (`docs/handoff-2026-10-12.md:3`). The 10-19 session hit its usage limit mid-run (log 06:21 to 08:20). A daily dollar cap cannot protect the window, because a burst of agent PRs is a burst of reviews. Only pause-on-signal and the 2-slot semaphore do. Evidence: `06-operations.md:9`; `docs/handoff-2026-10-19.md` log.

- **[github-ci] Concurrency groups evict before job-level filters run.** `types:` cannot filter on `changes.base`, a comment body or a label name. A filtered-out event still joins the group and replaces the pending entry, which silently drops an owner's `/assay override` or a retarget run. The fix derives the group key from the filter, sending events that will be filtered out to `noop-<run_id>`, and adds `queue: max` on the decide-only group. Evidence: R3-10 in `docs/review/03-adversarial-review-round-3.md`.

- **[github-ci] `pull_request_target` runs the default-branch workflow on github.com, not the base branch's.** The round-3 reviewer's first premise (an agent creates a base branch with a modified workflow) was wrong and was withdrawn. Only GHES before 3.20 behaves the old way. But `pull_request_review` and `labeled` run the PR's own workflow file, which made v1's decide-only forgeable (R2-1). And environment deployment-branch policies, not the trigger, are what guard secrets (R3-04). Evidence: `docs/review/03-...` §5 and R3-04; `docs/review/02-regression-pass.md` headline 1.

- **[github-ci] A neutral conclusion counts as passing for required checks, and it is per SHA across bases.** `neutral base-not-protected` on head H, followed by a retarget of the PR to `main`, opens a merge window before the new run re-stamps the check (R3-03). Rule: `base-not-protected` gives `failure`, never `neutral`, and every decide re-fetches `pull.base.ref`. Evidence: R3-03; `corpus/golden/rule-2-base-not-protected`.

- **[github-ci] GitHub has no single-user bypass actor in rulesets.** So doctor accepts only empty bypass lists (wi-66d1f8). There is also no read-none default `GITHUB_TOKEN`, so every workflow declares its own `permissions` (decision 0007 "Applied"). Evidence: `docs/handoff-2026-10-19.md` calls; `docs/decisions/0007`.

- **[github-ci] Workflow text can read differently to a parser than to GitHub.** In #284, the reviewer showed that bare carriage returns and tabs made a crafted workflow read one way to doctor and another way to GitHub. The fix refuses those forms outright and switches the trigger check to an allowlist (wi-5c7803, wi-d4c1d4: undeclared `permissions` count as write, and any mention of secrets counts as holding one). Evidence: `docs/handoff-2026-10-19.md` log 07:55, 08:35; #285.

- **[headless-agents] Agent sessions run with limited GitHub access.** In Claude Code cloud sessions GraphQL is blocked (`gh` REST only), user endpoints are blocked (the bot user id had to come from the owner, #273), and the environments API is unreachable (#43). A PR is marked ready with `POST pulls/N/ccr/ready_for_review`. Merges were sometimes "refused by the classifier", so PRs queued for the owner and dependent stories were stacked on their parent branch. Evidence: `docs/handoff-2026-10-12.md` "GitHub from this environment"; `docs/handoff-2026-10-19.md` log 02:50 and "Waiting on Ryan".

- **[headless-agents] Background agents stall silently on protected-file prompts.** Edits to `.github/`, settings, `AGENTS.md` and `Cargo.toml` prompt for approval, and background agents hang without a word. Runs therefore batch charter and manifest edits, and leave workflows as ready-to-apply diffs under `handoff/github-batch/` with charter rows under `handoff/afk4-agents-rows.md`. As a result, the pipeline workflows still do not exist in the repo: `workflows/README.md` reads "Empty until the pipeline stories". Evidence: `docs/handoff-2026-10-12.md` "Protected files"; `docs/handoff-2026-10-19.md` "Waiting on Ryan"; commit `91d0e53` (batched charter rows).

- **[github-ci] `gh` expands placeholders and drops proxy variables.** `gh api` fills in `{owner}`, `:owner`, `:repo` and `:branch` anywhere in a path, so an attacker-influenced path can be rewritten. The transport refuses these before gh runs. With a scrubbed environment, gh lost `HTTPS_PROXY` and the CA variables, so exactly those six are passed through (wi-fe594c). In the same round, a call struct's `Debug` printed the token (#293 F1). Evidence: `crates/assay-forge/AGENTS.md:46,102`; `crates/assay-forge/src/github/gh/environment.rs:2`.

- **[testing] ETXTBSY flakes from writing an executable in a multithreaded test binary.** If a sibling test forks while a spy script's write descriptor is open, exec fails with ETXTBSY. Renaming does not help, because the inode is the same. The fix has a child `install -m 0755` write the file into a staging directory and then renames it into place, so no thread of the test binary ever holds the file open for writing. Evidence: #176, `08bc61c` (#247); `crates/assay-cli/tests/it/support.rs:8-28`; `crates/assay-forge/src/process.rs:718-738`.

- **[github-ci] The GHCR package needs Actions write access set by hand.** `warm-target`'s publish failed with `permission_denied: write_package` on every push to main from 13 October until the package's Actions access was fixed in its settings. Its `verify` step proves only that an offline build works, not that dependencies were reused (A-29 unmeasured). Cargo fingerprints hold absolute paths, so build and restore both use `/work/ws`. Cargo hardlinks outputs, so the archive is packed with `--hard-dereference`. Evidence: `docs/handoff-2026-10-19.md` "Read this first"; #196; `docs/operations/warm-target.md`.

- **[github-ci] CodeQL flags decision text in test messages as cleartext logging.** A test assertion message that printed the decision reasons was flagged, and `fd69f39` removed it. Evidence: `fd69f39`, `7573521`.

## Lessons from history

- **[trust-security] Re-implementing a parser of the attacker's language never converges.** Mechanical validation (#86, PR #171) needed 8 review rounds: each one found a new way for model text to become live Markdown through a gap between the screen's CommonMark reading and GitHub's renderer. That led to #175 and the by-construction sanitiser in #88. The temper adapter (#63, PR #168) went through at least 4 rounds of lexer desyncs (Unicode, BOMs, edition tokens, `macro_rules!`-assembled attributes), and #64 through 5. That led to #172, a compiler-enforced `-F <lint>` backstop that catches attributes after macro expansion. #172 is still waiting on the owner. Evidence: `git log` "Validation review round 4"…"round 8" (#86), "#64 review round 4/5"; #175, #172; `9202058`, `e54c67a`.

- **[trust-security] Three spec-level adversarial rounds before code found critical mechanism flaws in fixes that were right in intent.** Round 2 found a forgeable decide-only (artifact selected by name, R2-1/2), unauthenticated Z2s artifacts (a hostile `build.rs` holds the runtime token, R2-3), a poisonable Actions cache (R2-4), and a cost model wrong in the direction that matters ($0.90 to $1.28 per PR). Round 3 found the owner's daily account reachable by agents (R3-01), comment-edit privilege escalation (R3-02) and the neutral-plus-retarget window (R3-03). Each fix records a VERIFIED or REASONED tag, and §5 lists the attacks that failed. Evidence: `docs/review/02-regression-pass.md` §2; `docs/review/03-adversarial-review-round-3.md` §4-5.

- **[human-decisions] The owner's daily account is the agent identity, which leaves no eligible approver.** Every PR an agent opens is authored by `Ryan-Britton`, because the cloud environment's GitHub token is that account's. Decision 0005 lists it in `agents` and `maintainers`, never in `owners` or `approvers`. So `owners ∪ approvers` is empty until #41: nothing can be owner-approved, and P10 stays a convention. The daily account is also an org owner, a privileged role an agent can reach. Evidence: `docs/decisions/0005-agent-identity-and-approver.md`; R3-01; #269.

- **[process] Stacked PRs and late merges caused semantic merge conflicts.** Because merges waited for the owner, the 10-19 session stacked stories on parent branches. On merge, #281's push model was replaced by #70's ledger records, #72's `CommandComments` port had to be folded into #58's, and two parsers of `.assay/owners` ended up coexisting (follow-up #305; #276 duplicates the Weigh-In triage rule). Each merge needed another review. Disk filled during a merge (18 GB freed). Evidence: `docs/handoff-2026-10-19.md` log 17:40, 18:05, 05:15, 05:40.

- **[cost-capacity] Liveness and identity checks broke on events that carry the default branch's SHA.** The reconcile sweep judged liveness by runs on the PR head, but requeue and decide-only runs carry the default branch's SHA (#295 round 1). Bundle provenance accepted only `pull_request_target`, which deadlocked requeued `workflow_dispatch` runs exactly on the trust-path PRs that needed approval (R3-08). The publish lock keyed on `RunUid` was re-entrant across jobs of one run, so the first release ended the other job's critical section (#288, fixed with #290). Evidence: `docs/handoff-2026-10-19.md` log 16:25; R3-08; #288.
