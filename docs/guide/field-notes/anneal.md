# anneal (becomes Bench): hard-won lessons

Mined from `/home/user/anneal` at `7f41aa2` (2026-11-01, 203 commits) and GitHub `Wet-Ink-Corporation/anneal`. The audit (`references/strategy/audit/anneal.md`) was read at `0d0a469` (2026-10-12), so this file covers what it does not: about 160 commits and PRs #114 to #201, among them PR 140 (install without binaries), PR 194 (the cockpit split), the guard hardening series (#115 to #188), and the Tier 3 eval rounds r4 to r7. Paths are relative to the anneal repo root.

## Guardrails

- **[hooks] With no binary anywhere, every hook exits 0, guards included, and SessionStart says why.** Before PR 140, the launcher exited 2 for `--fail-closed` hooks when no binary was found. claude.ai syncs plugins into cloud sessions without their `libexec/` builds, so every Bash, Edit, Write and Agent call was blocked, while the bootstrap hint claimed the gates were "off". The only way out was to remove the plugin. Ryan's call was "Warn, don't block": the launcher now exits 0 for any `hook` call, and for `hook bootstrap` it prints a `systemMessage` plus `additionalContext` naming the cause. Once a binary runs, a guard that fails or times out still blocks (`onFailure: block`). Evidence: PR 140 body; `plugin/libexec/anneal:21-25,236-247`; `plugin/libexec/anneal.cmd:32-38`; `d6a1616`, `a92410f`; AGENTS.md Plugin rules ("Hooks fail open, guards fail closed, a missing install warns").
- **[hooks] A test enforces `onFailure: "block"` exactly when the hook's args contain `--fail-closed`.** `hooks_manifest` checks several things: every entry uses exec form with an explicit timeout and `onFailure`; the failure policy matches the flag; every id is an `anneal hook` subcommand the binary accepts. It also checks that a strict DTO sidecar row exists, with a fingerprint over event, matcher and the compact hook JSON. A hook therefore cannot silently drift from fail-open to fail-closed, or the reverse. Evidence: `docs/hooks.md:34-41`; `crates/anneal-cli/tests/it/hooks_manifest.rs:104,145,361-496`.
- **[plugin-packaging] The cockpit mod lives in its own plugin, because a mod switches off the whole plugin in desktop chats.** In the Claude desktop app's merged Chat and Cowork, a plugin whose `hooks.json` names `modules` is switched off entirely, skills included ("this plugin entry is off here"), although the docs say chat ignores hooks. Weigh-In isolated the cause with uploaded copies on 2026-10-31. anneal moved the mod into `plugin-cockpit/` (`anneal-cockpit`), which carries byte-identical copies of the launchers, because one plugin cannot reach another plugin's root. Evidence: `docs/mods.md:5-11`; `349e71b`, `5feeb58`, `2c21f52` (PR 194); CHANGELOG.md:13; AGENTS.md decisions 2026-10-31.
- **[plugin-packaging] Versions and launchers must agree across both plugins, and CI checks it.** `scripts/check-versions.sh` fails unless all of the following hold: `Cargo.toml`, `plugin/.claude-plugin/plugin.json` and `plugin-cockpit/.claude-plugin/plugin.json` carry one version; `plugin-cockpit/libexec/{anneal,anneal.cmd}` are `cmp`-identical to `plugin/libexec/*`; and CHANGELOG has the section. Any duplicated launcher in the monorepo needs the same byte check. Evidence: `scripts/check-versions.sh:1-20`.
- **[process] A release includes a human check on every surface, because CI cannot see the desktop app.** CI and AFK sessions run only in Claude Code and cloud sessions. That is how a plugin the desktop chats switch off went unnoticed. The release checklist now has Ryan ask for one skill by name in the CLI, the desktop Code tab, a new desktop chat with a folder connected, and Cowork with the uploaded zip. Evidence: `docs/release-0.1.0.md:58-68`; AGENTS.md "A release is checked on every surface a person uses".
- **[trust-security] A model cannot record a human approval through Bash.** The guard's `human-only` rule denies a model's Bash call that runs `anneal verdict set … --actor human` or `anneal decide label … --actor human`. The merge gate counts a human `approved` only when `by.actor` is `human`; `--via` is kept for audit and never decides. A human approval with no actor no longer satisfies the gate. Evidence: CHANGELOG.md:26 and the `--actor`/`--via` entry; `docs/verdict.md:40-46,151-153` (wi-10f284); `504cc93`, `00d261d`; `docs/guard.md` §`human-only`.
- **[github-ci] The merge gate accepts exactly one canonical merge command and denies every other merge.** After six review rounds on PR 114 kept finding shell routes to `gh pr merge`, the gate judges only `gh pr merge <n> --match-head-commit <40-hex> --repo <host>/<owner>/<repo>`, run as a Bash call of its own with only plain words. `--repo` must equal the worktree's `origin`, because gh reads `--repo` before `GH_REPO`, `GH_HOST` and the working directory. A second pass is a best-effort tripwire: any word reading `merge` beside a gh name it could not resolve, `gh api`, a definition, or a program known only at run time is denied. Evidence: `docs/verdict.md:220-290`; `791cc4e` (#114); #116; CHANGELOG.md:66.
- **[trust-security] Text sent to Clef is redacted with an allowlist skeleton, after the denylist leaked.** Two PRs (#94, #95, "Hide the last cookie-pair redaction leaks") patched span-based secret redaction of the D1 command. The fix was to invert it: render only program names, keywords, wrappers, option names and separators, and replace every value with `<redacted>` unless a fixed table names it; a parse failure becomes `<unparsed>`. Evidence: `d2e340a` (#120, Ryan's card 2026-10-13); CHANGELOG.md:62; `5a9b0b7`, `17584b8`.
- **[hooks] Every hook caps stdin and reads only the fields it uses, all optional.** Caps are tuned per event: 64 KiB for SessionStart and SubagentStart, 1 MiB for the PreToolUse guards, 4 MiB for Stop and SubagentStop, 8 MiB for PostToolBatch, and 16 MiB for injection-scan. The serde `Input` structs are `#[serde(default)] Option<…>` with unknown fields ignored, so a new Claude Code field never breaks a hook, while a guard denies oversized or non-JSON input (`bad-input`). State files the hooks keep (`stop-blocks.json`, `bootstrap-sessions.json`) are refused unless `symlink_metadata` says they are regular files. Evidence: `docs/hooks.md:62,135,184,209,266,389`; `crates/anneal-cli/src/hook/completeness.rs:52,70-81`; `crates/anneal-cli/src/hook/bootstrap.rs:31,103-110`; `docs/guard.md:42`; `crates/anneal-cli/AGENTS.md:261`.
- **[hooks] Hook time budgets are measured inside the hook, not trusted to `timeout`.** The prompt hooks plan for 4.5 s of their 5 s timeout and ask Clef only while its full 2 s still fits. The guard gives git 1 s to find the ledger and each ledger statement 16 of its 100 ms, so a locked ledger still lets the deny out. The bootstrap bounds its live-state lookup (git 2 s, 0.5 s per statement) rather than raising its 15 s timeout: with the 10 s defaults, a stuck writer could cost about 100 s. Evidence: `crates/anneal-cli/src/hook.rs:44-48`; `crates/anneal-cli/AGENTS.md:126,131,310`; CHANGELOG 0.0.5 entry ("16 of 100 ms").
- **[testing] Platform facts are checked in the installed Claude Code binary's hook schema, never from memory.** The charter records each such fact with the version it was checked against (2.1.296). Examples: Stop gives `stop_hook_active` and `last_assistant_message`; SubagentStop has no timing or token fields, so duration comes from the transcript; `PostToolBatch` exists and fires once per parallel batch; `userConfig` keys arrive upper-cased as `CLAUDE_PLUGIN_OPTION_*`. Evidence: `crates/anneal-cli/AGENTS.md:229,245,253,267`.

## Patterns

- **[distribution] A launcher in `libexec/` that tries a ladder of sources and downloads a checksummed release when none is present.** The sh launcher picks the newest build among the platform's targets, so a stale native build never shadows a fresh cross-build. It then walks PATH, skipping its own directory by resolved path, with `ANNEAL_LAUNCHER` to stop recursion. Next it tries the cache at `~/.cache/anneal/<version>/<target>/`, and finally downloads `anneal-<target>` plus `SHA256SUMS` from release `v<version>`. Each try fits its hook's timeout (bootstrap 3 s + 10 s, other hooks 1 s + 3 s, plain calls 10 s + 60 s). Downloads resume, a `mkdir` lock goes stale after 2 minutes, a failure backs off for 2 minutes, curl is limited to `--proto '=https,file'`, and stdin is never read, so the hook's input still reaches the binary. Evidence: `plugin/libexec/anneal:26-234`; PR 140; `scripts/test-launcher.sh` (file:// release, hash mismatch, executable bit).
- **[skills-prompts] The SessionStart hook puts the plugin's `libexec/` on PATH through `CLAUDE_ENV_FILE`.** Skills run bare `anneal …` in Bash, but nothing had put it on PATH. `hook bootstrap` appends `export PATH='<root>/libexec':"$PATH"` to the env file Claude Code sources before each Bash call. It writes the line once per file (checked within 64 KiB, CRLF-tolerant), single-quotes the directory, refuses one holding control characters or `:`, and joins the path with `/` as text, because `Path::join` inserted a backslash on Windows. Evidence: `dfb5cb0`, `209ebd3`; `crates/anneal-cli/src/hook/bootstrap/env_file.rs`; wi-40630a; CHANGELOG.md:25.
- **[github-ci] Verdicts stay fresh across a rebase by patch-id.** A verdict is fresh for a head when it was recorded for that SHA, or when its `git patch-id --verbatim` matches the head's from the same base. The diff is pinned so the id depends only on content: `--no-color --no-ext-diff --no-textconv --no-renames --ignore-submodules=none --binary -U3 --src-prefix=a/ --dst-prefix=b/ <base>...<head>`. `--verbatim` keeps whitespace, because it is code in Python, YAML and Makefiles. The patch id is computed only when some verdict could be fresh by it. Evidence: `docs/verdict.md:128-143`; `crates/anneal-cli/src/pr_diff.rs`; `cdc9787` (#97).
- **[github-ci] A hook gate is mirrored as a GitHub commit status that branch protection can require.** `verdict set` posts the `anneal/verdict` status from the merge gate's own evaluation: `success` when the gate would allow the merge, `pending` while it still wants a verdict, `failure` on an outright deny. This moves enforcement to where every merge route passes, and it was #116's answer to "a hook can be a tripwire, never complete". Evidence: CHANGELOG `verdict set posts a GitHub commit status` entry; `c34e565` (#176); #116.
- **[human-decisions] Approvals are bound to content hashes, and races are read back.** `plan approve` records `sha256:` of the plan's bytes, and `plan check` compares only those bytes with the latest approval. A lost `append_if` race is read back: the same hash is "already approved" (exit 0), another hash is a conflict (exit 3). A spec names its design tree with a `Tree:` line, and approval is refused until a matching `grill_confirmed` exists. Evidence: `crates/anneal-cli/AGENTS.md:187,194`; `docs/plan.md`; `580ead3` (#77); `cb48822` (#76).
- **[hooks] The Stop hook keeps its own block cap of 2 (Claude Code's is 8) and resets it only on real progress.** The count lives in `~/.anneal/stop-blocks.json`, keyed by sha256 of the session id, at most 64 sessions. It resets on a stop with no gate, or when the transcript bytes since the last block contain `"type":"tool_use"`. On `stop_hook_active` the hook writes and counts nothing. If the count cannot be read or saved, the gates demote to context rather than blocking uncounted. Evidence: `docs/hooks.md:371-380`; `crates/anneal-cli/AGENTS.md:249-250`.
- **[headless-agents] The process runner is bounded, and it treats a grandchild that holds a pipe as a timeout.** `wait_with_deadline` drains stdout and stderr on named threads with a byte cap, and kills and reaps the child at the deadline. Output is complete only once every holder of the write ends has closed them, so a git wrapper running `sleep 30` used to hold the call. Now the call returns within the timeout plus about 100 ms, and the stuck reader thread is abandoned, holding at most `cap` bytes. When a child is fed stdin (the weigh-in bridge), only its output is waited on after it exits. Evidence: `crates/anneal-cli/src/process.rs:1-55`; `6e234d0` (#132), `b964fab` (#153); CHANGELOG.md:41.
- **[cost-capacity] Paid evals are gated twice and capped as a budget for starting work.** Tier 2 and Tier 3 run only when routing could have changed (`--changed-since <ref>` diffs `name`, `description`, `when_to_use` and the skill set). `--max-cost-usd` defaults to 25 (wi-92bc1b); each batch gets the remainder rounded down to the cent, and the with-arm gets at most half, so the baseline always has budget to compare against. A refused batch reports what it spent, marked as a lower bound. Gated tools and scaffolds need explicit `--allow-gated-tools` and `--allow-scaffolds`. Evidence: `evals/README.md:102,134,212,250-252`; `0d0a469` (#112); `603fa75` (#119).
- **[llm-judgement] Eval results are statistical, with intervals, not pass counts.** Routing uses 95% Wilson intervals. Uplift uses a Newcombe hybrid interval on with-minus-baseline, and its lower bound must be at least 0: 3 of 3 against 3 of 3 gives -0.561 to 0.561, so a case that passes either way cannot carry a skill. A regression suite fails when the Wilson upper bound of its pass rate is below 0.90. Evidence: `evals/README.md:109,229-231`.
- **[llm-judgement] Model gates ship in shadow and are promoted on calibration numbers.** Clef points log decisions without acting until a point has 50 answered decisions, Brier ≤ 0.15 and an ask rate below 20%. Threshold proposals minimise expected cost, with a false accept weighted 5:1 against a needless intervention. A human applies the change; there is deliberately no apply button in the cockpit. Any Clef failure (unreachable, timeout, bad response) never denies: in enforce mode it falls back to `ask`. Evidence: `crates/anneal-cli/AGENTS.md:271,282,285,293,299`; `docs/mods.md` ("No apply button"); #44.
- **[observability] One read model, `anneal status --json`, serves every UI, and the mod renders only that.** `status` folds the ledger and the anneal home into a versioned document (`schema: 1`, additive only). The mod keeps no state beyond its last reading, refreshes at most once a second, keeps the last good reading on failure, drops sections whose types do not match (and names them), and writes nothing. The rule is "hooks enforce, the mod shows and collects" (#56). Evidence: `581d927` (#58); `docs/mods.md:5-60`; `docs/status.md`.
- **[testing] Shell-wrapper grammars are pinned against the real binaries.** Wrapper option parsing (sudo, doas, env, xargs, chrt, ionice, su, watch …) follows each tool's getopt, taking the union where implementations differ. It is checked against installed binaries through `crates/anneal-cli/tests/fixtures/wrappers/probes.txt`, and bypass coverage is a hand-rolled combinatorial test (each denied command in each wrapping form and each pair of forms), since proptest was not approved. Evidence: `3a51d31` (#121); `docs/guard.md:339`; `crates/anneal-cli/AGENTS.md:140`.

## Gotchas

- **[distribution] claude.ai syncs plugins into cloud sessions without their `libexec/` binaries, and a marketplace that serves `main` has none either.** The synced copy under `~/.claude/plugins/synced/.../anneal/libexec/` held only the launchers. Any plugin with a native CLI needs a fetch-or-warn path. Evidence: PR 140 body; CHANGELOG.md:48.
- **[cross-platform] Claude Code's Bash sandbox mounts `/dev/null` over protected dotfiles in the working directory.** `.bashrc`, `.gitconfig`, `.claude/settings.json` and others appear as untracked character devices, so `git status` showed the tree dirty and every sandboxed session entered build mode with `clean: false`. The preconditions hook then denied every edit. The fix treats untracked character devices as not a change. Evidence: `116424a`; CHANGELOG.md:7.
- **[headless-agents] `claude plugin eval`'s Linux sandbox denies Bash writes under `/tmp`, `/var/tmp`, `/dev/shm` and `/run/shm`, and its socket paths overflow the 107-byte limit.** Every r4 Bash write, including the anneal ledger, failed with `Read-only file system`. In r5, 39 of 162 runs failed because the sandbox's bridge socket (`claude-eval-XXXXXX/tmp/claude-socks-<16hex>.sock`) sat 58 bytes below a long workspace name. The workspace moved out of `/tmp` and was shortened to `ae-<6 hex>/t`. Evidence: CHANGELOG.md:21,23; `bab5482`, `958740f`, `4420fcd`.
- **[trust-security] A plugin's hooks under `claude plugin eval` run on the host, outside the eval sandbox, with your rights.** Scaffold scripts do too. Tier 2 and Tier 3 should run in a container. Evidence: `evals/README.md:92,138,212`.
- **[headless-agents] A workspace that looks like the plugin repository confuses `${CLAUDE_PLUGIN_ROOT}` readers.** The with-arm copy was `plugin/`, and anneal's repo has `plugin/` at its root, so runs treated the workspace as the anneal repository. It was renamed `with/`. Evidence: CHANGELOG.md:9; `82bb54c`.
- **[skills-prompts] The bootstrap index must list only skills the installed plugin actually has.** Naming a skill the plugin lacks sends the model to `Unknown skill`. The index now checks `skills/<name>/SKILL.md` under `CLAUDE_PLUGIN_ROOT`, and fails open to the full list when a lookup errors. Evidence: CHANGELOG.md:12; `0b7f89e`, `9a10a43`.
- **[hooks] The Stop hook can rewrite the reply an eval grades.** Eval runs in the eval home counted its dotfiles as changed source, so completeness blocked and the graded reply changed. Every case now runs in its own repository, and graders read tool calls from the trace rather than only the final reply. Evidence: CHANGELOG.md:24; #201 ("graders read the trace").
- **[github-ci] Cloud sessions sit behind a TLS-terminating proxy, so a Rust client with bundled roots fails.** `verdict set`'s ureq client (webpki roots) exited 4 on every post in claude.ai cloud sessions. It now honours `HTTPS_PROXY`/`https_proxy`/`ALL_PROXY` and replaces the roots with `SSL_CERT_FILE` (regular file only, ≤ 4 MiB). A 407 is reported as "the proxy refused the tunnel", and errors name the variable, never its value. Clef's transport was left direct. Evidence: `d0b6692` (#195); wi-077990; CHANGELOG.md:8.
- **[github-ci] Agent sessions cannot edit `.github/`, so workflow changes are handed to the maintainer as a diff.** In PR 140 the Windows launcher smoke test in `ci.yml` stayed red until Ryan applied a 3-line patch the agent posted. The Tier 2/3 CI jobs exist only as text in `evals/README.md`. #116 lists `.github` changes as Ryan's for the same reason. Evidence: PR 140 comments; `evals/README.md:138`; #116.
- **[git] git 2.56 changed the message for a `.git` file pointing nowhere.** It now says "gitfile does not point to a valid repository" instead of "not a git repository". Code that classified stderr text broke on the macOS and Windows CI runners and on Dependabot PRs #137 to #139. Both messages now map to `NotARepository`. Evidence: `af95565`; PR 140 comment; CHANGELOG.md:47.
- **[git] A fixture repository needs `git init -b main`, because the default branch varies.** Without it, `floor-guard` found no `main` base. This requires git ≥ 2.28. Evidence: CHANGELOG.md:10; `82bb54c`.
- **[hooks] Hooks receive no Claude Code version, and `CLAUDE_CODE_VERSION` was seen stale.** No version warning is possible from a hook. Evidence: `crates/anneal-cli/AGENTS.md:127` (wi-319ca0).
- **[hooks] `/clear` gives the conversation a new session id.** State keyed by session must be re-injected after it. Evidence: `crates/anneal-cli/AGENTS.md:125` (wi-6f8350).
- **[hooks] Generated files are not source, but code under cache directories still is.** Edits gating on "source changed" tripped on `__pycache__`, `*.pyc`, `.pytest_cache`, `*.log` and similar. A review then caught that `*.py`/`*.toml` under `.cache` must stay source. Evidence: CHANGELOG.md:11; `0b7f89e`, `2b3cc9d`.
- **[llm-judgement] Skills under-trigger on ordinary phrasings.** Tier 3 r6 found five model-invoked skills missing prompts such as "add a flag" (build), "X should do Y but does Z, fix it" (diagnose) and new behaviour with no stated mechanism (grill). Triggers were widened against observed misses, not guessed. Evidence: `915a9e0`; CHANGELOG.md:15.
- **[cross-platform] Case-insensitive file systems let `RM -rf /` or `Git push -f` past name matching.** Protected paths match ignoring ASCII case, but program names other than `anneal` are matched as written. Evidence: `docs/guard.md` Limits (last item); `crates/anneal-cli/AGENTS.md:138`.

## Lessons from history

- **[trust-security] A shell-lexing denylist is an endless arms race, so build the real gate elsewhere.** After the audit, 38 commits touch the guard. They chase forms like `rm "$b"{-rf,/}`, extglob `@(-rf)`, `env -S` escapes, `su -- -c`, `sudo -iu`, `chrt -o`, `bash $o 'rm -rf /'`, `bash -[c]` beside a file named `-c`, and `watch -x sh -c` (#115, #121, #127 to #129, #150, #165). Six issues are still open (#144, #147, #163, #170, #171, #188), and Ryan ruled word splitting (#128) and `git push "$branch"` (#127, wi-5fe51a) documented gaps. The repository's own conclusion: a hook is a tripwire against mistakes, and the authoritative check must sit where every route passes (a GitHub required status, a sandbox). Evidence: `git log --oneline | grep -ic guard` = 38; `docs/guard.md:349-430`; #116.
- **[llm-judgement] Regex claim detection over prose keeps growing.** The completeness hook now carries a hand-built grammar: up to two filler words, conditional scopes ending at 19 irregular past verbs unless a determiner precedes, and clause breaks at `so` and `but`. It still accepts named false positives ("done reading the logs") and misses, and it leans on the block cap. Each round (#84, #135, #157) added rules. Evidence: `docs/hooks.md:310-347`; `47e8959`, `e1a7cc4`; #135 still open.
- **[testing] Each paid eval round found broken cases and graders before it measured skills.** In r4 to r7, every triage fixed the harness or the cases first. Examples: graders that counted a refused Edit or a red `task done` as success; `plan-before-source` with `max: 0` and no `min`, which could never pass; cases needing tests that already existed; a fixture whose fix was already committed; a plan that spelled out red/green steps, handing the process to the baseline arm; "graders that the baseline passed anyway". Budget a dry triage pass and check every grader against real good and bad replies before trusting uplift numbers. Evidence: #201; `b843964`, `d625764`; CHANGELOG.md:14,24.
- **[process] "Install without binaries" was found only by using the product on a new surface.** PR 140 started from a cloud session where the synced plugin blocked everything. The cockpit-off-in-chat bug was found by Weigh-In, not anneal's CI. Both led to the surface checklist. Evidence: PR 140; `docs/mods.md:5`; `docs/release-0.1.0.md:58`.
- **[human-decisions] "anneal never stores decisions" was broken by a one-way ruling.** wi-1154f8 records the orchestrator's reversible rulings as `orchestrate.ruled` in anneal's ledger, which blurs the weigh-in boundary. wi-d75b26 decided against a registry bump on #77 ("wording only") against the recommended option, accepting that "old ledgers read with new meaning" if wrong. Persisted-contract calls like these should get explicit flip conditions. Evidence: `.kb/_intake/decisions/wi-1154f8-*.md`, `wi-d75b26-*.md`.
- **[process] The AFK build granted "allowlist everything (temper asks dropped)" to stop permission prompts.** It was two-way, but it is the kind of setting that outlives the run. Evidence: `.kb/_intake/decisions/wi-f701c2-*.md`.
- **[hooks] Status-block grammars diverged between sibling plugins.** anneal's SubagentStop parser accepts `DONE|DONE_WITH_CONCERNS|NEEDS_CONTEXT|BLOCKED` and records temper's `WIP` as a violation, while temper's agents emit `DONE|WIP|BLOCKED`. This is still unresolved at HEAD. Evidence: `docs/hooks.md:394-400`; audit §4.

## Open problems

- **[distribution] The download is checksummed against the same release, and Windows never downloads.** SHA256SUMS from the same release catches corruption, not a tampered release. `anneal.cmd` has no download path, so a Windows install without builds stays off. Evidence: PR 140 "Not done here"; `plugin/libexec/anneal.cmd:1-11`.
- **[llm-judgement] Clef has never run live.** The model ids are placeholders (`@cf/wet-ink/clef{,-flash}`), and the Cloudflare secrets were still awaited at the last status. Every point is in shadow, so calibration has no real labels and #44 (v0.1.0) stays open. Outcome labels for D1, D4 and D6 are by hand (`decide label`) until hooks can see post-call signals. The 5-way concurrent D4 calls can also lose `counts.json` increments. Evidence: `plugin/playbooks/clef-thresholds.json:4-5`; `docs/decide.md:153`; #1 comment 2026-10-12; #44; `crates/anneal-cli/AGENTS.md:271,298`; `docs/hooks.md:296-298`.
- **[github-ci] The `anneal/verdict` status is a snapshot on one commit.** A rebase leaves the new head without one, even while the verdict stays fresh by patch-id, and no human override exists. Evidence: `docs/verdict.md:122-126`; #116, #175.
- **[trust-security] `human-only` reads only anneal commands.** A model that appends `"actor": "human"` straight to `~/.anneal/decisions/decisions.jsonl`, or writes the ledger with `sqlite3`, is not seen. Approvals from the cockpit (#62) are not built. Evidence: `docs/guard.md:409-411`; #62.
- **[hooks] The completeness hook judges only the final assistant message.** A claim made earlier in the turn is not seen. Any green `test_run`, even `git --version`, satisfies the gate, and `ledger append` can forge one. The design keeps an honest agent honest and is not a defence. Evidence: `docs/hooks.md:270-272,357-363`.
- **[testing] Paid eval CI and the dogfood run never happened.** There is no `ANTHROPIC_API_KEY` job in `.github/workflows/`, and #27 (dogfood on temper) and #44 are open. Whether the r7 cases now separate the arms "is measured by the next paid Tier 3 run". Evidence: `ls .github/workflows` (ci, release, rust); #201 acceptance; #27.
- **[headless-agents] Killing a timed-out child does not kill its descendants.** std cannot kill a process group without `unsafe`, so a looping caller such as `watch` (up to 1800 s) can leave one bounded reader thread per timed-out call. Evidence: `crates/anneal-cli/src/process.rs:39-46`.
- **[observability] Screenshots of the cockpit were never taken, and the mod is type-checked against a hand-written shim.** Drawing needs an interactive model session, and Claude Code's own mod declarations are not vendored, so the real engine checks the mod only through `claude plugin test`. Evidence: `docs/mods.md` "Screenshots", "Files" (`mod-types/mod-api.d.ts`).
