# Test strategy: `weighin`

The test strategy section of this crate's charter ([`AGENTS.md`](AGENTS.md)), kept here so the charter chain stays under the 24 KiB cap (`tools/charters/check.sh`).

Unit tests sit beside the code in `annotate`, `ci` (atoms, trailers, the append-only check and the report, all pure), `commands`, `env`, `store`, `context`, `git`, `harness` (`claude_code/tests.rs`: payload reading, the stdin cap per event, the timeouts against `hooks.json`, rendering goldens per event, entry-point detection, and the hook entry's failures, its stderr line among them), `hooks` (`errors.rs`: the error-log report, its tail cap and its files; `failures.rs`: the failure note, decision D2 B; `heartbeat/tests.rs`: the slot format, its classification at the boundaries, `status`'s read of a slot and the beater thread, HK-5), `journal` (committed-journal reading, refs budgets), `ops`, `pane`, `recall`, `shell_bin`, `state_file` (regular files only, HK-6), `text` and `main`; the ones that spawn processes or open SQLite carry `#[cfg_attr(miri, ignore = "...")]`. Integration tests in `tests/it/` compile as one binary over shared helpers in `support.rs`; `core_store.rs` runs the binary beside Core's 1.x ledger fixtures (`crates/core/redkiln-core/tests/fixtures/`, whose bytes each test writes into its own scratch repository; never opened in place, nor copied into this crate). `store/wire/tests.rs` holds the manual live-ledger check, ignored, run by hand with `WEIGHIN_LIVE_LEDGER`. The end-to-end tests in `cli.rs` (and the source write-back in `annotate.rs`) cover:
- a scratch repository;
- hooks fed the JSON Claude Code sends;
- a linked worktree;
- a sitting done through `batch`;
- the board round trip.

`journal_hooks.rs` covers the hooks' export (Stop exports, SubagentStop and PostToolUse do not, inbox fallback, a broken ref logged once, a hanging remote inside the timeout, Cowork, `hooks.json` timeouts), `journal_refs.rs` covers the `journal` subcommands over a bare `origin` and clones (export, inbox, relay, import, pre-push, envelopes and exit codes), `relay_workflow.rs` checks the relay workflow and runs its command, and `ci_check.rs` covers `ci-check` on real branches, over the `scratch.rs` repository, which gives each test its own temp dir. `repo_class.rs` covers the class from suite.toml and its fallback, and a `client` repository's gates. `owner.rs` covers the owner: suite.toml's, config.json's, and git's where there is no config, with git reading only a config each test writes (B-31). `pane.rs` covers what the local board pane needs (the state on stdout, one answer on stdin as surface `pane`, raw items read-only, mode `off`, no config). `recall.rs` covers the decisions an edit brings back (a match, no match, a reopened decision, the cap of three, a `Write`, a ledger that cannot be read, logged once and noted) and that capture beside it is unchanged. `hook_notes.rs` covers a failing hook's note in its output (CLI-09: once per unreported log, always when it cannot log, SessionStart's direct note, silence for other events) and a symlinked error log left alone. `heartbeat.rs` covers the hook heartbeat (HK-5): a finished slot, none without `redkiln/`, in Cowork or outside git, a dead slot logged once and reported, and a symlinked slot left alone. `status.rs` covers `status --json` (CLI-12): its envelope against `cli-envelope-1` and its `data` against `status-1` and the contract, the text form, an unlocated store off with `null`s, a refused store off and untouched, no store created, unusable events by type, hook errors and a lost hook degrading with nothing marked seen, the 1.x import reported due and not run (D3), and a closed stdout; `commands/status.rs` pins `health` against the findings. `eval_seed.rs` scores marker capture against the eval seed (`eval/`, #22); `cargo test -p weighin --test it eval_seed -- --nocapture` prints the scores.
