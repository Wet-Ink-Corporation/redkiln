# Test strategy: `redkiln-core`

The test strategy section of this crate's charter ([`AGENTS.md`](AGENTS.md)), kept here so the charter chain stays under the 24 KiB cap (`tools/charters/check.sh`).

Unit tests beside the code: the header, the transaction helper, tags and their registry, trust, ids, names, envelope fields, writing and reading, RFC 8785's vectors, `suite.toml`, git's deadline and cap. `tests/it/` (integration, no git): new, concurrent, WAL, refused and copied stores, conditioned appends, envelopes stored and read back amid foreign and unusable events, telemetry dropped under a held write lock, a read lock at commit and a held open lock, and kept to its window; the SPEC's goldens and schemas (`conformance`); the old-ledger fixtures in `tests/fixtures/` (by weighin 0.2.2 and 1.2.0 built from weigh-in's tags; 0.1.x's is 0.2.2's under WAL, as 0.1.x left it), opened only as copies, listing and bytes pinned by `tests/it/fixtures.rs`; beside them `core-store-hs1.sqlite3`, a Core store weighin 1.2.0's Core wrote on happenstance 0.4.5, which `tests/it/migrate.rs` opens (as copies) to pin ST-08's migration to happenstance schema 2. `tests/repos/`: journals, refs and location on real repos (subdirectories, a linked worktree, a broken `.git`, none). `tests/working_dir.rs`, the one test that moves the working directory, is its own binary; `repos` and `subject` start git, so stay apart: a child forked while another thread holds `<store>.lock` keeps it.
